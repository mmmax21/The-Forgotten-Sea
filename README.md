# 涌现 · 每日行动工作台

## 阶段 2：人物、地点与统一目标详情

沿用现有 Godot 4 / GDScript 主场景、五区布局和原回合逻辑。第 2 阶段完善已知资料、地图状态与行为选择，不实现行动队列、AP 扣除或夜间演算。

**默认运行显示正式资料。** 当前工程没有实际相识、发现、位置或存档记录，所以默认人物列表为空、位置显示未知。这不是初始化失败，也不会自动把四名 NPC 标成已经认识。

**查看开发预览：F5 运行 → F3 打开 DEBUG → 勾选“开发预览（隔离相识、发现与位置）” → 关闭 DEBUG。** 部分 Mac 键盘需按 fn + F3。预览会展示四名人物、三个地点、一个物件和一个异常。预览里的当前状态与位置为可替换的演示快照；退出预览后恢复正式资料，日期不变。

## 本阶段功能

- 四名人物为老渔夫、盐嫂、螺螺、哑伯。条目包含文字占位头像、姓名、最新已知状态；可局部滚动。
- 详情包含已知身份、占位立绘、对玩家的态度、对海的看法、合作范围、已发现的问题或线索、已知位置。没有统一好感条、说服百分比或精确信念增量。
- 老渔夫的私下信任与公开作证分开。关于孙子的顾虑只有发现后才显示，孙子不是螺螺。开发预览默认没有发现该顾虑，自动测试另行验证发现后的情况。
- 盐嫂的怨恨不等于加入；示例合作范围明确受已知生计和安全状况影响。
- 螺螺展示好奇与分享意愿，也展示已观察到的暴露风险；没有把他简化为效率数值。
- 哑伯以手势、指认和刻木表达合作；交流提示由已知的交流方式配置驱动，不展示正常口头长篇对话。
- 镇区、古代遗迹、区域边界为可配置地点。区分当前所在地、可到达、不可到达、调查线索；未发现地点不会出现在节点列表，也不能靠直接传入 ID 选中。
- 人物、地点、物件、异常使用统一目标 ID、已知资料投影与选择机制。
- 按钮适用性同步更新：异地或位置未知的人物不能选交谈；调查需要已发现的明确线索且目标在同地；当前所在地不重复移动，不可达边界说明已知的第三法则限制。
- 可用行为按钮仅选择意图，有选中反馈。切换目标清除旧意图，重新验证按钮事件。加入行动槽与结束今日行动仍禁用；不会执行行动、扣 AP、移动或获得新情报。

## 打开、运行与验收

用 Godot 4 导入 `project.godot`，按 F5。初始窗口 1920×1080，最小 1280×720；无需 .NET、第三方插件或外部美术素材。

```sh
godot --path /path/to/taptap
```

开发时也可显式使用独立预览参数：

```sh
godot --path /path/to/taptap -- --preview-targets
```

本机可执行文件位于 `/Users/maxlou/Downloads/Godot.app/Contents/MacOS/Godot`。

建议检查顺序：

1. 默认启动确认没有被自动加入的已认识人物；通过 F3 勾选开发预览。
2. 选择四个人物，比较态度、看法与合作范围；老渔夫详情不应出现尚未发现的孙子顾虑。
3. 选择螺螺：预览中他的已知位置在古代遗迹，玩家在镇区，交谈禁用。该位置仅用于开发验证，不是正式剧情安排。
4. 选择哑伯并滚动右侧，点击交谈，只出现手势/指认/刻木的配置提示。
5. 选择镇区，普通地点没有调查权限；选择贝壳，可选择调查意图，但不能加入计划。
6. 选择区域边界：可查看资料，移动禁用，并显示第三法则限制。
7. 在 1280×720 和 1920×1080 间缩放，列表与详情局部滚动，底部保持固定。
8. 关闭预览，确认示例人物和地点消失，预览选择与意图清空，日期未变。
9. DEBUG 保留旧回合推进与确认跳天；取消/关闭/Esc、第 10 天禁用、最终结算和重开仍按原规则工作。

## 正式资料接入接口

`GameScreen.set_known_world(definitions, snapshot)` 接收正式目标定义和正式知识快照，然后重建已知列表与详情。也可编辑正式目录和初始知识文件用于后续正式流程接入。

- 定义包含 `id`、`kind`（person/place/object/anomaly）、`name`、`avatar`、`facts`。
- 每条事实有 `id`、`field`、`text`。字段可为身份、态度、信念、合作、说明、交流方式、问题或线索；调查线索显式带 `investigable: true`。
- 快照 `known_targets` 的键决定玩家认识/发现了哪些目标。目标记录中的 `fact_ids` 决定已经发现哪些事实，`latest_fact_id` 必须也在其中才会显示为最新状态。
- `known_location` 是已知位置记录；缺失时显示未知，不根据职业或 UI 布局推测。位置指向未发现地点时也不会公开该地点。
- `current_location_id` 与目标已知位置决定同地/异地；`known_routes` 提供已知可达性及可公开的原因。
- 未发现事实从列表、详情、悬停说明和行为判定中一起排除。读取返回深拷贝，选择操作不写入知识。
- 标有 `preview_only: true` 的快照会被正式接入接口拒绝。开发预览使用独立定义与独立快照，不覆盖正式资料。

当前示例中的信任、风险、生计、位置和可达性都仅保存在独立预览配置中，不作为每局必然剧情。没有写死解锁日期、组织条件、行动费用或成功公式。

## 验证

无图形测试：

```sh
godot --headless --path /path/to/taptap --script res://tests/run_tests.gd -- --small
```

图形测试与截图：

```sh
godot --path /path/to/taptap --script res://tests/run_tests.gd -- --capture
godot --path /path/to/taptap --script res://tests/run_tests.gd -- --small --capture
```

在 macOS / Godot 4.7.2 / Compatibility 渲染器上，两组图形测试各 **340 项检查、0 失败**。覆盖正式/预览隔离、每个人物条目的实际点击、详情滚动、行为选择、知识零写入、隐藏信息过滤、位置变更后的资格变化、未发现目标、普通地点禁止调查、边界不可达、窗口动态缩放，以及原回合推进与结算。已检查两种分辨率的实际截图。

其他操作系统、其他 Godot 版本，以及未来剧情/存档系统的真实接入尚未验证。中文依赖系统中文字体。
